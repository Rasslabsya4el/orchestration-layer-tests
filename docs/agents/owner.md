# Как владелец работает в этом репо

Что добавляет этот репозиторий — в `docs/agents/local/owner.md`, читай его, если он есть.

Плейбук владельца для orchestration v2. Протоколы самих чатов:
`docs/agents/brain.md`, `docs/agents/orch.md`. Как агенты просят у тебя readings и
присылают прогресс, записано в `docs/agents/brain.md` ("The owner", "Talking to the owner").

## Какой чат для чего

У ORCH нет своего чата: чат "Orch" ушёл на покой, ORCH — фоновая сессия Claude Code, которая берёт сразу все
готовые issue и ведёт их параллельно через своих сабагентов; запускает и досматривает её диспетчер
`tools/agentops/dispatch.py` (отдельный процесс, не чат). Сессий ORCH как можно меньше: следующая стартует, только
когда каждая живая уже заканчивает (`finishing`).

| чат / процесс | кто | модель / effort | ты ему пишешь | Remote Control |
|---|---|---|---|---|
| чат брейна | brain | Fable 5.1 high (когда лимит Fable кончится: Opus 5.5 xhigh) | всё: идеи, тикеты, вопросы, решения, "что там с #N?" | ON, единственный |
| диспетчер ORCH (`python -m tools.agentops dispatch`, фон) | — | не Claude, детерминированный скрипт | ничего | — |
| фоновая сессия ORCH (одна зараз, `orch <номера issue>`, все готовые issue параллельно) | ORCH | Sonnet 5.5 high, permission mode auto | ничего; смотреть — `tools\agentops\agents.cmd` | OFF |

Брейн никогда не работает сам: он пишет issue и сразу свободен для разговора, задачу делает ORCH в фоне. Диспетчер сам
видит issue с меткой `ready-for-agent` без исполнителя (сначала те, где последний комментарий — результат runs daemon)
и, когда живой сессии ORCH нет или каждая живая уже заканчивает, запускает одну фоновую сессию ORCH со всеми готовыми
issue; живой сессии он будит новые готовые issue. ORCH режет каждую issue на юниты, ведёт их параллельно через
сабагентов, закрывает каждую с цифрами и заканчивает свой ход, когда больше ничего не держит, — без /clear и без
сообщений о пробуждении. Remote Control включён только у брейна: сессию с
Remote Control нельзя очистить, поэтому у фоновых сессий ORCH и у остальных фоновых чатов он выключен. Нужен effort выше для одного
трудного решения: подними его в UI брейна на пару ходов и верни обратно.

### Как посмотреть на ORCH

`tools\agentops\agents.cmd` (или `agents.ps1`) открывает `claude agents` — список фоновых сессий в этом репо.
Пробел — заглянуть в сессию, не мешая ей; Enter — подключиться и написать; стрелка влево — отключиться, сессия
продолжает идти в фоне. `CLAUDE_EXE` переопределяет путь к `claude.exe`, если автопоиск не находит его.

## Как надиктовывать идеи

Просто говори брейну. Всё, что влияет на будущую работу, он записывает в тот же момент, а не держит в чате:

| что ты сказал | куда записывается |
|---|---|
| сырая идея | issue с `needs-triage` |
| решение по задаче | в issue |
| важное решение | ADR в `docs/adr/` |
| новое слово | `GLOSSARY.md` |
| твоё предпочтение | memory |

Брейн спрашивает тебя только о том, что знаешь только ты: чего ты хочешь, что болит, что тебе нравится, сколько
денег, времени и риска ты готов отдать. Остальное (как это устроить, в каком порядке, какие пороги) он выясняет и
решает сам и пишет тебе одной строкой, с причинами; твоё «почему?» решение не отменяет. Решения по коду и
архитектуре принимают агенты; тебе приходит эффект в цифрах билдов.

## Когда делать /clear

- **Брейн:** когда он сам предложит (все его сабагенты закончили, всё записано). Он даёт готовый follow-up для
  нового старта; /clear теряет только болтовню. Можно и без его предложения: спроси сначала "всё записано?".
- **ORCH:** /clear не нужен — это фоновая сессия, которая держит все готовые issue сразу; диспетчер сам
  останавливает её (`claude stop`), когда она закончила ход, и запускает следующую в свежей сессии, когда появятся
  готовые issue.

## Как смотреть прогресс

- Спроси брейна "прогресс": он присылает таблицу прогресса и оценку до готовности.
- По конкретной задаче: issue на GitHub, ORCH пишет туда чекпоинт на каждом этапе ("done / next / numbers /
  branch") и закрывает с цифрами.

## Что требует тебя

- **Разрешения.** Больше никто не просит тебя запускать команды: каждая сессия работает в bypass permissions за
  permission guard (`tools/hooks/permission_guard.py`, red list в ADR про permission guard). Отказ guard разбирается по `docs/agents/workflow.md`,
  не на тебе. Единственное ручное действие, которое осталось: переключить permission mode чата в приложении, если чат
  старше `guard install`.
- **`ready-for-human`.** Readings (папка, точные файлы, на что смотреть: `docs/agents/brain.md`) и решения,
  которые можешь принять только ты. Список: `gh issue list --label ready-for-human`.
- **`needs-info`.** Вопрос вне спеки: ORCH паркует issue, брейн приносит вопрос тебе.
- **Лимиты.** Когда лимит модели подходит к концу, скажи брейну, сколько осталось: он предложит момент передачи
  (`docs/agents/sessions.md`, "Limit handover protocol"). Кончился лимит Fable: переключи брейн на Opus 5.5 xhigh.
